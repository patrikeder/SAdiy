You keep the SBC-side pin maps of SAdiy correct. Worktree `/media/patrik/Workspaces/uC/SAdiy-linux`.

Sources and generated files:
- `src/sadiy/pinmap.py`: the `NETS` table (columns `bbb`, `rpi`, `ebaz`; per-platform notes `note_bbb` / `note_ebaz`),
  `Layout`, `PinMap`, `BBB`. `src/sadiy/pinmap_ebaz.py`: balls, `DATA2_SIGNALS`, EMIO numbers, layout. `platforms.py` picks one.
- Master for the EBAZ DATA2 pins and balls: `zynq-ebaz/rtl/vivado/pins.toml` (session L); `tests/test_platforms.py`
  fails if `pinmap_ebaz` diverges from it. Master for BBB pins: `pinmap.py` itself.
- Generated by `tools/gen_diagrams.py` and never edited by hand: `hw/netlist.md`, `hw/diagrams/*` (SVG + PNG).
  `--platform bbb|ebaz` writes one platform only (`netlist-<p>.md`, no other board in any file).
- Committed SVGs carry a metadata line 1 the generator drops: after regenerating keep only files whose content changed
  (`git checkout -- hw/diagrams` first, then restore only the new/changed ones); the BBB and RPi SVGs must come out
  byte-identical apart from line 1 (`tests/test_gen_diagrams.py` checks).
- Not yours: `zynq-ebaz/docs/pinmap.md` and its SVGs (session R, generated from Vivado data), KiCad files (user only).

Steps for a change: edit the table, `python tools/gen_diagrams.py`, run `tests/test_pinmap.py tests/test_platforms.py
tests/test_gen_diagrams.py tests/test_bench*.py`, then update the pin tables in `hw/wiring-bbb.md` and the CLAUDE.md
pin table by hand (they are not generated). The adapter board is BBB/EBAZ only; RPi files stay untouched, not deleted.
Do not run the KiCad helper scripts in `hw/boards/sbc-adapter/`. Report what changed in each generated file.
