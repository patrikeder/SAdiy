# Bring-up test plan, 2026-11-07

Starting point: BBB GPIOs seen working (pin map and PE4302 lines move). SPI0 and I2C2 not yet. Goal for today: **SPI and I2C working, ADF4351 locked at a known frequency, detector curve and PE4302 weights measured.** The mixer and IF stage are out of scope (IF filter, IF amp and LPFs are not built, see `hw/todo-parts.md` and `bringup.md` stage 3).

Dependency order. SPI gates the ADF4351. The ADF4351 is the only RF source, so it gates the detector curve, the PE4302 weights and the amp. I2C only gates the ADS1115, so it runs in parallel with the RF work (the DMM covers the detector until then).

```
A  SPI0 ──► C  ADF4351 locks ──► D  detector curve ──► E  PE4302 weights ──► F  amp (stretch)
B  I2C2 / ADS1115 ───────────────────────┘ (ADC compared with DMM in D)
```

Rule for every stage: tick a box only when its pass criterion is met, and note the measured value next to it. Save captures in `captures/bringup-2026-11-07/` (git-ignored).

## 0. Before starting (15 min)

- [ ] Build and send the package so the BBB runs the current code (working tree has the new logging; the package name ends in `-dirty`): `python tools/make_bbb_package.py`, then the update steps in `deploy/bbb-setup.md`.
- [ ] On the BBB run `sweepd` by hand with trace logging, so every SPI word shows in the terminal (trace logs SPI words and sweep points; I2C accesses are not promised to appear): `cd /opt/sadiy && sudo PYTHONPATH=src python3 -m sadiy.server.sweepd --bench-only -vv --config /etc/sadiy/local.toml`. GUI from the PC: `python -m sadiy.ui.sa_gui --host <bbb-ip> --connect`, Pins tab, Enter bench mode.
- [ ] Rails with a DMM (only if not done yet): 3.3 V at the PE4302 pads and ADS1115 VDD, 5 V at the ADF4351 jack and detector, amp and AD831 rail 9 to 11 V. Jumpers per `hw/boards/sbc-adapter/README.md`: JP3 fitted, J12 1-2 (CE high), JP5 fitted (or the board already pulls PDR up), **JP6 open until step D1 has checked the divider output**.
- [ ] **ADF4351 RF output into a 50 ohm load, not the mixer, until stage C passes.** Unused complementary output terminated too.
- [ ] Have at hand: SMA attenuators totalling 20 dB (10 + 10 is fine) and 3 / 6 / 10 dB spares, a 50 ohm feed-through for the MSO5354, SMA cables. Missing attenuators block D and E; if you have none, do A, B, C and stop.

## A. SPI0 (45 min)

Pins: SCLK P9.22 (pad 84), MOSI P9.18 (pad 86), CS0 = LE P9.17 (pad 87), MISO P9.21 (pad 85, unused). Pad numbers are from the AM335x pad table from memory, so check them against the `pins` file's own labels.

1. [ ] Overlay applied: `grep uboot_overlay /boot/uEnv.txt` has `uboot_overlay_addr4=BB-SPIDEV0-00A0.dtbo` (uncommented, and `enable_uboot_overlays=1`), and `ls /dev/spidev*` shows a node. `dmesg | grep -i spi` and `cat /sys/bus/spi/devices/*/modalias` should name `spidev`. Write the node number into `/etc/sadiy/local.toml` (`bench.spi_bus`).
   - No node after a reboot: wrong overlay name for this kernel (`ls /boot/dtbs/$(uname -r)/overlays | grep -i spi`), or `uEnv.txt` line commented or overwritten by a script. Check that `/proc/device-tree/ocp/spi@48030000/status` says `okay`.
2. [ ] Pin mux is SPI mode 0 on the four pads: `sudo grep -E '^pin (84|85|86|87) ' /sys/kernel/debug/pinctrl/*pinmux*/pins`. The last hex digit of the register value must be `0` (GPIO would be `7`). If it is not, the overlay did not claim the pads.
3. [ ] Logic analyzer on adapter test points (TP_SYN_*) or the ADF4351 J6 header: CLK, DAT, LE, 3.3 V logic, SPI decoder mode 0 (CPOL 0, CPHA 0), 32 bits, MSB first. Raw access page, ADF4351: send the **outputs-off R4 word `0x008C8004`** (the one the driver itself writes as its safe state; the daemon refuses a word that enables an output anyway).
   - Pass: CLK idles low, 32 rising edges at 1 MHz, DAT carries `0x008C8004` MSB first, LE low during the transfer and rising after the last clock. Compare with `python tools/bringup.py adf4351-pattern --word 0x008C8004`.
   - Edge-order failures: LE not moving = CS0 pad not in SPI mode or wire open; CLK idle high = mode not 0; bytes in wrong order = not MSB first (check the `-vv` log against the capture).
4. [ ] Amplitude and ringing at the ADF4351 end: edges clean, levels 3.3 V (220 ohm series resistors on the adapter). Slow the clock (`bench.spi_hz = 250000`) if edges are bad.
5. [ ] Repeat the word 10 times from the GUI (Patterns page, repeated ADF4351 frame, Export CSV) and check that the capture never misses a frame or a clock.

Pass: stage A ticked when step 3 matches on the capture.

## B. I2C2 and the ADS1115 (30 min, parallel to A if hands allow)

Pins: SCL P9.19 (pad 95), SDA P9.20 (pad 94). I2C2 already has pull-ups on the BBB (the adapter's 4.7k are DNP).

1. [ ] `ls /dev/i2c-*` and `i2cdetect -l`: note the bus number (expect `i2c-2`) into `bench.i2c_bus`. Pads in mode 3: `sudo grep -E '^pin (94|95) ' /sys/kernel/debug/pinctrl/*pinmux*/pins`, last digit `3`.
2. [ ] DMM, BBB running, nothing else: ADS1115 VDD 3.3 V, ADDR at GND (address 0x48), SDA and SCL both high at about 3.3 V idle.
3. [ ] `sudo i2cdetect -y -r 2` shows `48`. Config register: `sudo i2cget -y 2 0x48 0x01 w` prints `0x8385` (the chip's power-on 0x8583, byte swapped by i2cget). Same from the Raw access page: 0x8583.
   - Nothing at 0x48: DSLogic on SDA and SCL with the I2C decoder while `i2cdetect` runs. No ACK = wrong address (check ADDR strap), no power, breakout pins crossed (SDA and SCL swapped is common), or a short. SDA held low = a device or a solder bridge pulls it.
4. [ ] Convert A0 with the A0 input shorted to GND: code within a few LSB of 0. Then a DMM-measured 1.000 V (from a divider off 3.3 V) on A0: reading within 0.1 % of the DMM at the 4.096 V range (125 uV per LSB).
5. [ ] A0 to the detector output (detector powered, no RF yet): ADS1115 volts equals the DMM on TP_DET_OUT. Expect about 1.9 V or more with no signal, and the A0 clamp keeps it under 3.3 V.
6. [ ] AIN0 cross-check: **before** fitting JP6, measure the divider tap on the adapter with the detector powered and no RF. It must read about 0.751 x the detector voltage and **below 1.8 V**. Then fit JP6 and read AIN0 on the Raw access page: it should agree with the ADS1115 reading times 0.751, within a few mV.

Pass: ticked when 3 and 5 hold. 6 is a nice-to-have today.

## C. ADF4351 locks (60 min)

`Adf4351.registers()` (R0..R3, R5) is now written but **unchecked against ADI's software**. Get the six words with `python tools/bringup.py pll --mhz 100` (outputs off in R4, LD pin = digital lock detect in R5). Before sending them, generate the same configuration in ADI's evaluation software (ACE or ADIsimPLL: ref 25 MHz, PFD 25 MHz, fundamental feedback, RFOUTA -4 dBm, digital lock detect on LD) and compare word by word. Fields that may legitimately differ are the charge pump current (R2, depends on the board's loop filter) and the clock divider value (R3); anything else is a bug to fix in `drivers/adf4351.py` and in `tests/test_adf4351_registers.py`.

1. [ ] Raw access, ADF4351 page: send R5, R4 (outputs off), R3, R2, R1, R0 in that order, 100.000 MHz. Then read SYN_LD on the Pins page.
   - Pass: LD = 1 and the board's lock LED is on. LD stays 0: check reference (25.000 MHz oscillator on, 5 V jack powered, CE and PDR high), word order, and that R0 was sent last. A word sent while LE does not move (stage A) is silently lost.
2. [ ] Tick the main output, Apply (the GUI only allows this after you have sent registers). MSO5354 on the output through the 50 ohm feed-through: 100 MHz, about 0.4 Vpp (-4 dBm) minus cable loss. Note whether AOUT+ or AOUT- gives the usable level on the eval board (`config/default.toml` comments say VERIFY which feeds the mixer).
3. [ ] Step three more frequencies (50, 200, 350 MHz, each with its own words and the output re-applied), LD = 1 each time and the scope frequency within 1 kHz. Note the level change with frequency.
4. [ ] Power steps -4, -1, +2, +5 dBm at 100 MHz (R4 power field): scope level rises in about 3 dB steps. Do not exceed +5 dBm into anything but the scope.
5. [ ] Spectrum look at harmonics with the MSO5354 FFT or the second scope: second and third harmonic levels written down (they set the LPF requirement in `todo-parts.md`).

Pass: LD high and the right frequency on the scope at 100 MHz and at one other point.

## D. Detector curve and ADC path (45 min)

Chain: ADF4351 (100 MHz) -> attenuator stack -> detector RF in. Output voltage on the DMM and on the ADS1115.

1. [ ] Source level at the end of the cable with nothing but the feed-through: measure on the scope, this is the reference (accuracy of a scope amplitude is roughly 1 dB, say so in the notes).
2. [ ] Add attenuators in steps (0, 10, 20, 30, 40 dB, at -4 dBm start) and record scope level (while above about -20 dBm), DMM volts and ADS1115 volts for each. Plot or tabulate volts against dBm.
3. [ ] Repeat at 50, 200 and 350 MHz (use the stage C words).
4. [ ] Compute slope and intercept per frequency. Pass: -24.5 mV/dB within tolerance over at least 40 dB. Put the values into `detector.slope_v_per_db` and `detector.intercept_dbm`; note the level where the curve flattens (`floor_dbm`, `max_dbm`).
5. [ ] ADS1115 agrees with the DMM within 2 mV across the range; note noise (stdev of 50 reads at the highest and lowest level).

Pass: ticked when step 4 passes.

## E. PE4302 weights and polarity (45 min)

Chain: ADF4351 -> **20 dB of attenuators (so the input to the module is about -24 dBm; the walk tool wants below -20 dBm)** -> PE4302 -> detector. No amp in this test.

1. [ ] Stop `sweepd` first: the walk tool opens the GPIOs itself. On the BBB: `PYTHONPATH=src python3 tools/bringup.py pe4302-walk --gpio 66,67,69,68,45,44`.
2. [ ] Per stage switched in, the detector output must **rise** by weight x 24.5 mV (V1 about 12 mV, V2 24, V3 49, V4 98, V5 196, V6 392) if the order and polarity are as assumed. Average the DMM reading for a few seconds per stage; V1 is near the noise, so use the ADS1115 average for it.
3. [ ] If a stage does the opposite, `--active-low`; if the order differs, record the real order. Write the result into `attenuator.weights_db` and `attenuator.active_high` in `config/default.toml`, then `pytest -q`.
4. [ ] Set 0 / 8 / 16 / 31.5 dB from the Raw access page (make-before-break) and check the detector change against the slope from D: 0.5 dB accuracy is the goal, 1 dB is acceptable for today.
5. [ ] Quick DSLogic check of the make-before-break order: `python tools/bringup.py pe4302-pattern --db 16 --from-db 15.5` and the capture of V1..V6 for that step, lowest attenuation never below 15.5 dB.
6. [ ] BBB reset (or `Leave bench mode`) leaves the module at 31.5 dB (R27..R32 pull-ups and the safe state). Watch it on the detector.

Pass: weights and polarity known and written to the config.

## F. Amp, if time is left (30 min, stretch)

- [ ] Amp rail measured (6 to 12 V). Chain: ADF4351 -> 20 dB pad -> PE4302 (10 dB) -> amp -> scope on 50 ohm. Expected output about -5 dBm (0.36 Vpp) if the amp really gives 31 dB. Gain at 50, 100, 200 and 350 MHz. Above 350 MHz the scope is out of range, so skip that today.
- [ ] Step the PE4302 down in 2 dB steps while watching the output; stop at the first sign of compression (a deviation of 1 dB from the expected output). That is a rough P1dB, not a calibration.
