# SAdiy: notes for Claude Code

DIY swept spectrum analyzer (low-IF receiver from ready-made modules). **The main controller board is the EBAZ4205 (Zynq-7010); the BeagleBone Black is only a backup** (user, 2026-11-25). Python first, C++/Rust only if a measured per-point time demands it. Read `README.md`, `docs/architecture.md`, `docs/gui.md`, `hw/netlist.md` and `hw/wiring-bbb.md` before changing anything, and `docs/handoff.md` first when starting on a machine you have not used before. The design review and the claude.ai Project "DIY Spectrum analyzer" are not in the repo; the facts that matter are summarised here.

## Rules (from the user)

- **Do not install any software without asking first.** That includes `pip install`, `apt`, npm and so on. If a package is missing (PyQt5, pyqtgraph, pyzmq), say what is needed and ask. Use the existing `.venv`.
- Do not run the KiCad helper scripts in `hw/boards/sbc-adapter/` (`gen_schematic.py`, `place_*.py`, `align_components.py`, `remove_rpi.py`). They only record how the first version was made. The `.kicad_*` files are edited by hand in KiCad; do not rewrite them.
- `hw/netlist.md` and `hw/diagrams/*` are generated by `tools/gen_diagrams.py` from the pin map in `src/sadiy/pinmap.py`. Edit those and regenerate; never edit the outputs by hand. Committed SVGs carry a metadata block on line 1 that the generator drops, so keep the regenerated files only where the content changed.
- The Raspberry Pi connector was removed from the adapter board: **no Raspberry Pi** from now on (the adapter was made for the BBB; the main board is now the EBAZ4205, see above). The repo-wide RPi files (`hw/wiring-rpi.md`, RPi columns in the netlist, RPi software paths) were deliberately left untouched. Do not extend RPi support; do not delete it unasked either.
- Commit only when asked. Match the existing style: small modules, hardware access only in `hal/`, logic without Qt in `*_core.py`-style modules, tests for everything that runs on a PC.

## Working on several machines

Only one machine works on the project at a time; `origin` (GitHub) is the single source of truth. Start a session with `git pull` and `docs/handoff.md`; end it with the tests, a commit and `git push`, and update the "State at last handoff" section there. Claude's local memory is not shared between machines (and is empty): put durable decisions and facts in this file or in `docs/`, not only in memory. Git-ignored data (`captures/`, `cal/*.json`, `dist/`) does not travel; see `docs/handoff.md`.

## Hardware facts (verified from photos unless marked)

- Chain: RF in -> PE4302 -> amp (30 dB) -> AD831 mixer -> detector (AD8318 class, about -25 mV/dB); ADF4351 is the LO. No LPF, DC block, pad, IF filter or IF amp built yet. **Status 2026-11-23: the AD8318 detector module is dead and no replacement is bought.** The mixer works (user checked its IF with the scope's FFT). On the EBAZ4205 the IF is to be digitized instead: two 30 MHz low-pass modules in series, then an AD9226 module (12 bit, 50 MS/s), ordered; facts and open points in `zynq-ebaz/docs/adc-module.md`, wiring in `hw/boards/ad9226-module.md`. The PL front end for it is in register map 1.3 (`FE_*`, test sources only until the pins exist on adapter v2). The BBB has no PL and keeps the analog plan (detector into AIN0, below) with no detector for now.
- **PE4302 module: parallel only.** 7-pin header GND, V1..V6 = 0.5, 1, 2, 4, 8, 16 dB, high = stage in. Module has 10 kohm pull-downs on V1..V6, so open inputs = 0 dB. Supply 3.3 V on two pads (not on the header). V6 goes through a series 10 kohm: check that 3.3 V drive switches the 16 dB stage. Weights and polarity are still to be confirmed with `pe4302-walk`.
- **The PE4302 is driven by a PCF8574 on I2C** (user decision, 2026-11-25; no SBC pin drives V1..V6). The expander sits on an I2C-to-LCD adapter board: V1..V3 on P0..P2, P3 = that board's backlight, V4..V6 on P4..P6 (there is no V0), P7 written high. Address 0x27 (`[attenuator] pcf8574_address`; a PCF8574A is 0x38..0x3F), 100 kHz maximum. It drives high only weakly: **every V line needs a 2.2 kohm pull-up to 3.3 V** (the adapter's R27..R32), and the expander board must run from **3.3 V**. All six lines change with one byte; where stages switch both ways it is two bytes in one transaction, the new stages first (make-before-break). The same port mapping is in `drivers/pcf8574.py` and in the PL engine (`pcf8574_att.sv`); `zynq-ebaz/sw/tests/test_pcf8574_matches_pl.py` compares the software with the PL model. **Not yet run with a real expander.**
- **ADF4351 eval board:** 25.000 MHz oscillator (PFD 25 MHz). Powered from a 5 V DC jack (on-board AMS1117-3.3); never feed its `3V3` header pin. Header: `GND CE LE CLK LD | 3V3 GND DAT MUX PDR`. `CE` and `PDR` must be high. Two complementary outputs AOUT- / AOUT+; terminate the unused one. Use `LD` for lock detect.
- **ADF4351 RF outputs are off by default** (`Adf4351.__init__` writes an outputs-off R4 first). Keep it that way. Outputs turn on only via `enable_output()` / `set_outputs()` after lock.
- **The ADS1115 is removed** (user decision, 2026-11-25; it had been the main ADC on every platform since 2026-11-05). The next detector ADC is the AD9226 on the EBAZ4205's PL; the BBB has only AIN0 (`[adc] kind = "bbb_iio"`, `detector.divider_ratio` stays 1.0 in the default config, which simulates); the EBAZ4205 has no ADC in bench mode.
- **Detector** (dead since 2026-11-23, see Chain; the numbers describe the module as it was) output reached about 1.9 V. BBB on-chip ADC (AIN0, P9.39) is the BBB's only detector ADC; it is 0 to 1.8 V absolute maximum, so there is a divider (ratio 0.751, `adc.ain0_divider_ratio`). Its analog return is GNDA_ADC (P9.34). Reference VDD_ADC (P9.32) must not be loaded.
- **BBB image (read from the board, 2026-11-07):** Debian Trixie, kernel 6.18, Python 3.13. No `config-pin` and no cape-universal. I2C2 is on (`/dev/i2c-2`). SPI0 needs `BB-SPIDEV0-00A0.dtbo` as an overlay. sysfs GPIO bases are 608, 512, 544, 576 for banks 0 to 3, and chip labels are misleading, so `hal/linux.py` finds banks by hardware address.
- Test instruments: several DMMs, Rigol MSO5354 (350 MHz), Rigol DS2072 (200 MHz), DSLogic logic analyzer.

## BBB pin map (a proposal until verified on the image; single source is `src/sadiy/pinmap.py`)

| Net | Pin | Notes |
|---|---|---|
| SYN_CLK / SYN_DATA / SYN_LE | P9.22 / P9.18 / P9.17 | SPI0, mode 0, MSB first, 32-bit words, LE = CS0 |
| SYN_LD | P9.23 | lock detect, input |
| SYN_CE | P9.27 | optional, CE header pin is jumpered high on the adapter |
| I2C_SCL / I2C_SDA | P9.19 / P9.20 | I2C2, PCF8574 of the PE4302 attenuator (EBAZ4205: DATA2-20 / DATA2-11, `/dev/i2c-0`) |
| DET_ADC | P9.39 AIN0 | cross-check, via divider, 1.8 V max |

Free on a stock image: P8.7-P8.19 and P8.26 as GPIO (P8.7..P8.12 were the attenuator lines until 2026-11-25: the adapter board as drawn still routes them to the PE4302 header, so they must stay inputs while the PCF8574 is wired there; J10, the former ADS1115 header, gives the PCF8574 3V3, GND, SCL, SDA on pins 1..4, see `hw/boards/sbc-adapter/README.md`). Not usable: P8.3-6 and P8.20-25 (eMMC), P8.27-46 (HDMI/LCD), power and ground pins. 220 ohm series resistors sit at the BBB header on every signal on the adapter.

## Platforms

`src/sadiy/platforms.py` picks a `pinmap.PinMap`: `pinmap.BBB` (the BBB map above) or `pinmap_ebaz.EBAZ` (EBAZ4205 DATA1/2/3, from `zynq-ebaz/rtl/vivado/pins.toml`, checked by `tests/test_platforms.py`). `sweepd --platform` / `[platform] name` chooses it (default bbb); `status` and `bench_open` return it, and the bench, GUI Pins tab and `tools/gen_diagrams.py` all read the same map. The `NETS` table in `pinmap.py` has a column per platform (`bbb`, `rpi`, `ebaz`); a note that differs per platform is `note_bbb` / `note_ebaz`. The no-Raspberry-Pi rule above still holds for the adapter board. The EBAZ4205 is the main SBC; the software's default platform is still `bbb` (`config/default.toml`, `platforms.DEFAULT`), so name it with `--platform ebaz` where it matters.

## Architecture in one paragraph

`sweepd` is the only process that touches SPI, I2C, GPIO and the ADC; it publishes sweeps over ZeroMQ PUB (5556) and takes commands over REQ/REP JSON (5557). GUI and terminal clients never touch hardware and can run on another host. Layering: `hal` -> `drivers` -> `core` -> `server` -> `ui`. `hal/base.py` has the interfaces, `hal/linux.py` the real backends, `hal/fake.py` recording fakes. Bench mode (Pins tab, `docs/gui.md`) lives in `server/bench.py`, which enforces the safety rules, and is exclusive with sweeping. Per point the sweep engine waits for lock detect, takes the median of the ADC reads and flags points (unlocked, overload, at floor, outlier, image not suppressed) in an optional fourth frame part, and can sweep twice with the LO on both sides to remove the low-IF image (`image_reject`, off by default); trace modes, markers and peak search stay in the GUI. Logging (`logs.py`): levels error to trace, stderr/journald on the BBB, a numbered ring served by the `log` command and published on topic `log` for the GUI's Device log (Advanced tab); trace never leaves the BBB. `patterns.py` already makes PE4302 write sequences and ADF4351 SPI frames for logic analyzer comparison.

## EBAZ4205 port

`zynq-ebaz/` holds the **main target** (the BBB is the backup), with the same adapter board and the same `sweepd`: Linux on the PS (`zynq-ebaz/sw/`) and an optional PL sweep engine (`zynq-ebaz/rtl/`). Two sessions work on it in worktrees: session L (Linux, branch `linux`, `../SAdiy-linux`) and session R (RTL, branch `rtl`, `../SAdiy-rtl`); the plan, ownership rules and the `seam:` commit rule for edits outside `zynq-ebaz/` are in `zynq-ebaz/docs/ebaz4205-zynq-plan.md`, the state in `zynq-ebaz/docs/STATUS-linux.md`, `log_linux.md`, `log_rtl.md`. The PetaLinux project is outside the repo (`/media/patrik/Workspaces/HW/ZYNQLinux/ebaz4205_sadiy/`); the files that matter are mirrored in `zynq-ebaz/sw/deploy/petalinux/`. ADF4351 CE is Linux's (EMIO 6, line 60); since register map 1.1 CE goes through the PL pin mux: while `STATUS.pin_owner_act` is 1 the engine drives it (`ADF_PINS.ce`) and Linux's state is ignored. **Register map 2.0** (2026-11-25): the engine writes the PE4302 through the PCF8574 itself, so while it owns the pins it owns I2C0 too (Linux must not use `/dev/i2c-0` then); the former PE4302 pins DATA2-14..19 are spare EMIO GPIO (port names `pe4302_v[0..5]` kept). The software refuses map 1.x bitstreams, including the one in the `BOOT.BIN` of 2026-11-15. EBAZ code reaches the board with `zynq-ebaz/sw/deploy/deploy_to_board.sh`; nothing of it has run on a sweep yet.
