# SAdiy: notes for Claude Code

DIY swept spectrum analyzer (low-IF receiver from ready-made modules) controlled by a BeagleBone Black. Python first, C++/Rust only if a measured per-point time demands it. Read `README.md`, `docs/architecture.md`, `docs/gui.md`, `hw/netlist.md` and `hw/wiring-bbb.md` before changing anything. The design review and the claude.ai Project "DIY Spectrum analyzer" are not in the repo; the facts that matter are summarised here.

## Rules (from the user)

- **Do not install any software without asking first.** That includes `pip install`, `apt`, npm and so on. If a package is missing (PyQt5, pyqtgraph, pyzmq), say what is needed and ask. Use the existing `.venv`.
- Do not run the KiCad helper scripts in `hw/boards/sbc-adapter/` (`gen_schematic.py`, `place_*.py`, `align_components.py`, `remove_rpi.py`). They only record how the first version was made. The `.kicad_*` files are edited by hand in KiCad; do not rewrite them.
- `hw/netlist.md` and `hw/diagrams/*` are generated by `tools/gen_diagrams.py` from the pin map in `src/sadiy/pinmap.py`. Edit those and regenerate; never edit the outputs by hand. Committed SVGs carry a metadata block on line 1 that the generator drops, so keep the regenerated files only where the content changed.
- The Raspberry Pi connector was removed from the adapter board: **BBB only** from now on. The repo-wide RPi files (`hw/wiring-rpi.md`, RPi columns in the netlist, RPi software paths) were deliberately left untouched. Do not extend RPi support; do not delete it unasked either.
- Commit only when asked. Match the existing style: small modules, hardware access only in `hal/`, logic without Qt in `*_core.py`-style modules, tests for everything that runs on a PC.

## Commands

```
. .venv/bin/activate
pytest                                  # all passed at last check; GUI tests are skipped without the GUI deps
python -m sadiy.server.sweepd --sim &   # simulated chain, tcp 5556 (frames) / 5557 (commands)
python -m sadiy.ui.sa_gui --sim         # GUI against its own simulator
python -m sadiy.server.sweepd --bench-only       # on the BBB: only bench mode, real hardware (add --sim for the fake board)
python -m sadiy.server.sweepd -v ...              # log level: -q warning, default info, -v debug, -vv trace (ssh only); or [log] level in the config
python -m sadiy.ui.cli_client --log-level warning # terminal client: sweepd's log history, then live
python -m sadiy.ui.sa_gui --host <bbb-ip> --connect   # GUI against a real sweepd
python tools/bringup.py pe4302-pattern --db 16 --from-db 15.5
python tools/make_bbb_package.py         # BBB package in dist/ (git-ignored); update it whenever code the BBB runs changes
```

GUI tests run offscreen (`QT_QPA_PLATFORM=offscreen`). PyQt5, pyqtgraph and pyzmq must already be in `.venv`; if not, ask.

## Hardware facts (verified from photos unless marked)

- Chain: RF in -> PE4302 -> amp (30 dB) -> AD831 mixer -> detector (AD8318 class, about -25 mV/dB); ADF4351 is the LO. No LPF, DC block, pad, IF filter or IF amp built yet.
- **PE4302 module: parallel only.** 7-pin header GND, V1..V6 = 0.5, 1, 2, 4, 8, 16 dB, high = stage in. Module has 10 kohm pull-downs on V1..V6, so open inputs = 0 dB. Supply 3.3 V on two pads (not on the header). V6 goes through a series 10 kohm: check that 3.3 V drive switches the 16 dB stage. Weights and polarity are still to be confirmed with `pe4302-walk`.
- **ADF4351 eval board:** 25.000 MHz oscillator (PFD 25 MHz). Powered from a 5 V DC jack (on-board AMS1117-3.3); never feed its `3V3` header pin. Header: `GND CE LE CLK LD | 3V3 GND DAT MUX PDR`. `CE` and `PDR` must be high. Two complementary outputs AOUT- / AOUT+; terminate the unused one. Use `LD` for lock detect.
- **ADF4351 RF outputs are off by default** (`Adf4351.__init__` writes an outputs-off R4 first). Keep it that way. Outputs turn on only via `enable_output()` / `set_outputs()` after lock.
- **ADS1115** (I2C, 0x48, ADDR to GND) is the main ADC, also on the BBB, for consistency between platforms (user decision, 2026-11-05). BBB I2C2 on P9.19 / P9.20, through the adapter board. No divider on this path (`detector.divider_ratio` = 1.0).
- **Detector** output reaches about 1.9 V. BBB on-chip ADC (AIN0, P9.39) stays wired as a cross-check; it is 0 to 1.8 V absolute maximum, so there is a divider (ratio 0.751, `adc.ain0_divider_ratio`). Its analog return is GNDA_ADC (P9.34), used only for this cross-check; the ADS1115 needs just I2C2 and board GND. Reference VDD_ADC (P9.32) must not be loaded.
- **BBB image (read from the board, 2026-11-07):** Debian Trixie, kernel 6.18, Python 3.13. No `config-pin` and no cape-universal. I2C2 is on (`/dev/i2c-2`). SPI0 needs `BB-SPIDEV0-00A0.dtbo` as an overlay. sysfs GPIO bases are 608, 512, 544, 576 for banks 0 to 3, and chip labels are misleading, so `hal/linux.py` finds banks by hardware address.
- Test instruments: several DMMs, Rigol MSO5354 (350 MHz), Rigol DS2072 (200 MHz), DSLogic logic analyzer.

## BBB pin map (a proposal until verified on the image; single source is `src/sadiy/pinmap.py`)

| Net | Pin | Notes |
|---|---|---|
| SYN_CLK / SYN_DATA / SYN_LE | P9.22 / P9.18 / P9.17 | SPI0, mode 0, MSB first, 32-bit words, LE = CS0 |
| SYN_LD | P9.23 | lock detect, input |
| SYN_CE | P9.27 | optional, CE header pin is jumpered high on the adapter |
| ATT_V1..V6 | P8.7, 8, 9, 10, 11, 12 | GPIO numbers 66, 67, 69, 68, 45, 44 (bank*32+bit, not sysfs); adapter has 2.2k pull-ups, default 31.5 dB |
| I2C_SCL / I2C_SDA | P9.19 / P9.20 | I2C2, ADS1115 (main ADC) |
| DET_ADC | P9.39 AIN0 | cross-check, via divider, 1.8 V max |

Free on a stock image: P8.7-P8.19 and P8.26 as GPIO. Not usable: P8.3-6 and P8.20-25 (eMMC), P8.27-46 (HDMI/LCD), power and ground pins. 220 ohm series resistors sit at the BBB header on every signal on the adapter.

## Architecture in one paragraph

`sweepd` is the only process that touches SPI, GPIO and the ADC; it publishes sweeps over ZeroMQ PUB (5556) and takes commands over REQ/REP JSON (5557). GUI and terminal clients never touch hardware and can run on another host. Layering: `hal` -> `drivers` -> `core` -> `server` -> `ui`. `hal/base.py` has the interfaces, `hal/linux.py` the real backends, `hal/fake.py` recording fakes. Bench mode (Pins tab, `docs/gui.md`) lives in `server/bench.py`, which enforces the safety rules, and is exclusive with sweeping. Per point the sweep engine waits for lock detect, takes the median of the ADC reads and flags points (unlocked, overload, at floor, outlier, image not suppressed) in an optional fourth frame part, and can sweep twice with the LO on both sides to remove the low-IF image (`image_reject`, off by default); trace modes, markers and peak search stay in the GUI. Logging (`logs.py`): levels error to trace, stderr/journald on the BBB, a numbered ring served by the `log` command and published on topic `log` for the GUI's Device log (Advanced tab); trace never leaves the BBB. `patterns.py` already makes PE4302 write sequences and ADF4351 SPI frames for logic analyzer comparison.
