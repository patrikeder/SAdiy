# Standalone DSP modules (`rtl/dsp/`): interfaces for later integration

Written by session R, 2026-11-15. These modules are **not in the bitstream**. Each one is built and tested on
its own: a bit-exact Python reference (`sw/sadiy_ebaz/dspref.py`), a testbench in `rtl/sim/tb_dsp_*.sv` that
compares word for word, and an out-of-context place and route (`rtl/scripts/synth_dsp.sh`). Nothing here has run
on the board. The engine itself is described in `rtl-spec.md`; the sample stream format in its section 8b.

Common rules: one clock `clk` (100 MHz), synchronous active-low `resetn`, no vendor cells, all data two's
complement. `valid` is one clock per item. Where a module can stall its input it has `s_ready`; outputs have no
back pressure (the consumer must take every `m_valid`).

## Overview

| Module | Does | Reference | Testbench | LUT | FF | BRAM | DSP | WNS at 100 MHz |
|---|---|---|---|---|---|---|---|---|
| `fft_r2` | FFT of 4 .. 4096 complex points, optional Hann window | `fft_ref` | `tb_dsp_fft` | 604 | 273 | 7.5 tiles | 4 | +1.60 ns |
| `fir_mac` | complex FIR, up to 64 taps, decimation (RBW shaping) | `fir_ref` | `tb_dsp_fir` | 401 | 86 | 0.5 | 2 | +2.10 ns |
| `iq_power` | re^2 + im^2 as mantissa / exponent | `power_ref` | `tb_dsp_power` | 165 | 192 | 0 | 4 | +5.82 ns |
| `adc_ad9226` | AD9226 pins to the sample stream | `ad9226_ref` | `tb_dsp_adc` | 37 | 49 | 0 | 0 | +5.91 ns |
| `adc_spi_sar` | 16-bit SPI SAR ADC to the sample stream | `spi_sar_ref` | `tb_dsp_adc` | 83 | 84 | 0 | 0 | +3.90 ns |

Numbers are from the out-of-context build of 2026-11-15 (xc7z010clg400-1, inputs and outputs unconstrained, so
they are register-to-register figures; `fir_mac` was measured before nothing changed in it, `fft_r2` after the
output-address fix). All five together: about 1300 LUT, 8 BRAM tiles, 10 DSP. Helper files: `tdp_ram.sv` (true
dual port RAM), `fft_twiddle_rom.sv` (generated by `rtl/dsp/gen_dsp.py`, do not edit).

## Where they go later

```
ADC pins -> adc_ad9226 / adc_spi_sar -> sample stream (det_ext_* of sadiy_top)
sample stream -> if_power: NCO, mixer, CIC  --I/Q, 18 bit, at fs / R-->  fir_mac  -->  power sum   (swept RBW)
                                                                    \->  fft_r2 -> iq_power -> result RAM  (FFT)
```

What the integration still needs (not done, on purpose):
1. `if_power` must export its filter output (I, Q, 18 bit, one `valid` per decimated sample). Today it only
   squares it internally. The export is the signal `yi / yq` with `v5`.
2. Registers: FIR (`ntaps`, `decim`, `shift`, coefficient address / data like `GEN_ADDR / GEN_DATA`), FFT
   (`logn`, `hann`), a third detector mode in `DET_CFG.mode` (it is one bit today).
3. A place for N results per point: the result RAM holds one word per point, an FFT gives up to 4096. Either one
   FFT frame per sweep "point" with the bins written to consecutive result words, or a second memory.
4. The model (`ebaz_pl_model.py`) calls `fir_ref` / `fft_ref`; the `tb_dsp_*` checks become part of a `sadiy_top`
   testbench.
5. Pins and clock of the ADC in `pins.toml` (session L) and the I/O registers in the board top.

## `fft_r2`

`X[k] = (1/N) sum x[n] exp(-j 2 pi k n / N)`, N = 2^logn.

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `logn` | in | 4 | frame size 2 .. 12 (4 .. 4096 points); taken with the first sample of a frame |
| `hann` | in | 1 | 1 = Hann window; taken with the first sample |
| `s_valid`, `s_ready` | in / out | 1 | one input sample per clock when both are 1; `s_ready` is 0 while a frame is computed and sent |
| `s_re`, `s_im` | in | 24 | input sample; **|re|, |im| <= 2^22** (then no stage can overflow) |
| `m_valid` | out | 1 | N clocks in a row, bins in natural order 0 .. N-1 |
| `m_index` | out | 12 | bin number |
| `m_re`, `m_im` | out | 24 | bin |
| `m_last` | out | 1 | with bin N-1 |
| `busy` | out | 1 | a frame is being loaded, computed or sent |

- Arithmetic: per butterfly `t = (b * w) >> 17` (floor of the complex product's sum), `a' = (a + t) >> 1`,
  `b' = (a - t) >> 1`; `w = round(131071 exp(-j 2 pi k / 4096))`. Every stage halves, so the result is the DFT
  divided by N; a full-scale tone lands in its bin with its input amplitude. Error against an exact DFT:
  truncation of a few LSB per stage, plus a gain error of up to 7.6 ppm per stage because the twiddle factors
  are scaled by 131071 and not 131072 (at most 0.0008 dB at 4096 points; 16 LSB on a full-scale 4-point frame).
- Hann window: applied to the bins, `(2 X[k] - X[k-1] - X[k+1]) >> 2` (indices wrap). No window table and no
  multiplier. Bin k = N/2 is the Nyquist bin; negative frequencies are bins N/2 .. N-1.
- Time for one frame: N clocks in, `2 N logn` clocks computing (4 per butterfly), N + 4 clocks out. 4096 points:
  about 1.1 ms. One butterfly unit; the memory is used in place.
- An 18-bit input (the filter output) should be shifted left by 4 before the FFT: that keeps the 2^22 limit and
  the most precision.

## `fir_mac`

`y[m] = sat18((sum_{t < ntaps} coef[t] x[n - t]) >> shift)` at `n = decim - 1, 2 decim - 1, ...`.

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `clr` | in | 1 | one clock: forget the history (start of a measurement) |
| `ntaps` | in | 7 | 1 .. 64 |
| `decim` | in | 8 | 1 .. 255, 0 = 1 |
| `shift` | in | 5 | right shift of the sum before the saturation; 17 for taps that sum to 131071 (gain 1) |
| `coef_we`, `coef_addr`, `coef_data` | in | 1 / 6 / 18 | coefficient write port; write while no output is being computed |
| `s_valid`, `s_ready` | in / out | 1 | input handshake |
| `s_re`, `s_im` | in | 18 | input sample |
| `m_valid` | out | 1 | one output |
| `m_re`, `m_im` | out | 18 | output, saturated |
| `m_sat` | out | 1 | with `m_valid`: this output was clipped |

- `coef[0]` multiplies the newest sample. Samples from before `clr` count as 0, so the first outputs show the
  filter filling up (drop `ntaps / decim` outputs, as `IF_CIC.skip` does for the CIC).
- One output takes `ntaps + 4` clocks, in which `s_ready` is 0. The source must leave that time between two
  samples: after a CIC with R >= 68 at one sample per clock this is always true for 64 taps.
- Coefficients come from software: `dspref.gaussian_taps(ntaps, bw_rel)` gives a Gaussian RBW filter
  (`bw_rel` = 3 dB bandwidth / input sample rate). A CIC droop correction can be folded into the same taps.

## `iq_power`

`m_pwr = {exp[5:0], mant[21:0]}` with `re^2 + im^2 = mant << exp`, truncated: the format of the result words
(`rtl-spec.md` 8c, decoded by `ifpath.decode`).

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `s_valid`, `s_re`, `s_im` | in | 1 / 24 / 24 | complex sample (an FFT bin) |
| `s_user` | in | 13 (parameter `UW`) | travels with the sample: bin index, last flag |
| `m_valid`, `m_pwr`, `m_user` | out | 1 / 28 / 13 | 4 clocks later |

One sample per clock, no handshake. `if_power` contains the same steps for its own sum; when the FFT is
integrated, `if_power` could use this module instead.

## `adc_ad9226`

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `enable` | in | 1 | 0: no clock to the ADC, no samples |
| `div` | in | 8 | clocks per ADC clock period, >= 2: 2 = 50 MSPS, 4 = 25 MSPS |
| `phase` | in | 8 | 0 .. div-1: the clock of the period in which the registered pin value is taken (0 = the clock in which `adc_clk` rises) |
| `twos` | in | 1 | 1 = the ADC is strapped for two's complement output |
| `adc_clk` | out | 1 | to the ADC; high for the first half of the period |
| `adc_d`, `adc_otr` | in | 12 / 1 | the ADC's pins |
| `valid`, `data`, `ovr` | out | 1 / 16 / 1 | sample stream: `data = (code - 2048) << 4`, `ovr = OTR` |

- The pins pass two registers before they are used, so the instant that counts is two clocks before `phase`.
  Tested with a model whose outputs are undefined from 2 to 7 ns after the clock edge: `div / phase` = 4 / 3,
  2 / 1 and 10 / 6 never sample in that window. **On hardware the right phase depends on the board delay: check
  with a known input and the `ovr` / code pattern, and try the neighbouring phase.**
- Integrated since register map 1.3 through `adc_fe` (rtl-spec.md 8d; `FE_CFG.div` / `phase` are these two ports). In
  the board top `adc_clk` goes through an OBUF (ADC_PADS build), and `adc_pins.xdc` puts the first pin register into
  the I/O cells and makes the pads false paths (the capture phase is software-chosen). The sample rate must keep its harmonics away from the 10.7 MHz IF (plan, F3).
- The AD9226 delivers a sample 7 clock periods after it was taken; that latency is constant and not corrected.

## `adc_spi_sar`

| Port | Dir | Width | Meaning |
|---|---|---|---|
| `enable` | in | 1 | |
| `period` | in | 16 | clocks per sample (1000 = 100 kSPS) |
| `t_conv` | in | 16 | clocks CNV stays high (the conversion time of the part, plus margin) |
| `sck_div` | in | 8 | clocks per SCK half period, >= 3 |
| `cnv`, `sck` | out | 1 | to the ADC |
| `sdo` | in | 1 | from the ADC |
| `valid`, `data`, `ovr` | out | 1 / 16 / 1 | sample stream: `data = code >> 1` (0 .. 32767), `ovr = 0` |

- Sequence: CNV high for `t_conv`, CNV low, half an SCK period, 16 SCK pulses; SDO is taken in the last clock of
  each high phase, MSB first. This is the 3-wire mode of the AD7685 / ADS8860 class as I remember it:
  **verify the timing against the datasheet of the part that is fitted** (which edge shifts, the time from CNV
  low to the first valid bit, the maximum SCK rate at 3.3 V).
- If `period` is shorter than `t_conv + (33 x sck_div)` clocks the cycles simply follow each other.

## How to work on them

```
rtl/scripts/gen.sh              # also runs rtl/dsp/gen_dsp.py (twiddle table, vectors)
rtl/scripts/sim.sh tb_dsp_fft tb_dsp_fir tb_dsp_power tb_dsp_adc
rtl/scripts/synth_dsp.sh [top]  # out-of-context build, results in build/dsp/
rtl/scripts/test.sh             # everything, including lint of these modules
```

Change the arithmetic in `dspref.py` first, regenerate, then make the RTL match. Deliberate faults that the
testbenches catch (checked 2026-11-15): wrong butterfly partner, missing window, wrong product term (FFT);
reversed history order, no zero history (FIR).
